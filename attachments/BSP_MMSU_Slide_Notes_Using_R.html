1. The one question everything is answering

The entire slide deck — every function, every test, every output table — is trying to answer one question:

The question Did the treatments cause the groups to perform differently?

In the demo, five groups of rats were given different treatments. We measured how many maze arms they entered correctly. The question is simply: are those five groups meaningfully different from one another, or could the differences we see just be random chance?

Every step that follows is either preparing to answer that question, answering it, or checking that the answer is trustworthy.

2. Loading your data into R

Slide: "R reads it in one line" 
d <- read.csv("ecig_memory.csv")

This is the only line that actually brings your data into R. Everything else works on data that is already loaded. Think of it as opening a file in Excel — except R holds the whole spreadsheet in memory under the name d, and you refer to columns with the $ sign: d$correct, d$group, and so on.

The file must be a CSV (comma-separated values). If your data is in Excel, save it first: File → Save As → CSV. That single step is the bridge between your spreadsheet and R.

The most common error here R says "cannot open file — No such file or directory." This almost always means R is looking in a different folder from where the file is saved. The fix: in RStudio, go to Session → Set Working Directory → To Source File Location. Then try again. The Survival Guide covers this in detail under Section 5.

3. Looking at what you loaded

Slide: "Step 1 — Read it, and look at it" 
str(d)
head(d)
tapply(short$correct, short$group, mean)

These three lines do not analyse anything. They let you inspect what R actually received, before you trust any results. Think of this as opening the spreadsheet and scanning it for obvious problems before you start calculating.

FunctionWhat it shows you
str(d) The structure: how many rows, how many columns, and what type each column is. A column of numbers that came in as text (chr instead of num) will break every statistical test. This is how you catch it early.
head(d) The first six rows, so you can see whether the data looks like what you entered. If the first row contains a group label instead of a number, something went wrong at the save step.
Why this matters Half of all "it won't work" moments in R happen because a column that should be a number was read as text, or a column name has an extra space. Running str(d) first catches this in seconds. Skipping it and going straight to the statistics means debugging a confusing error later.

4. Computing group averages with tapply

Slide: "Step 1 — Read it, and look at it" 
tapply(short$correct, short$group, mean)

tapply stands for "table apply." It takes three ingredients:

  1. The column of values — here, short$correct, the number of correct entries per rat per trial.
  2. The grouping column — here, short$group, which treatment group each rat belongs to.
  3. The function to apply — here, mean.

It splits the values by group, then computes the mean for each group separately. The result for this data is:

CONTROL  MO_ONLY  ECIG_ONLY  MO_ECIG  DPL_ECIG
   6.05     6.35       5.95     4.90      5.35

In ordinary language: on average, CONTROL rats entered 6.05 correct arms; MO_ECIG rats entered only 4.90. There is a visible difference. But visible is not the same as statistically reliable. The averages could differ just because of random variation between individual rats — five rats per group is a small number. That is what the next step tests.

Note on the subset The code uses short, not d. The full dataset has both short-term and long-term memory trials. The line short <- subset(d, term == "short") creates a smaller table containing only short-term rows. The group comparison is run on that smaller table so the two memory types are not mixed together.

5. Running ANOVA — the main comparison

Slide: "Step 2 — Compare the groups (ANOVA)" 
fit <- aov(correct ~ group, data = short)
summary(fit)

ANOVA stands for Analysis of Variance. Despite the name, it tests whether means differ — it does so by comparing how much the groups vary against how much individual subjects within the same group vary.

The ~ symbol (tilde) means "depends on" or "explained by." So correct ~ group means: "I want to know whether the correct-entry count depends on which group the rat was in." The thing being explained goes on the left; the thing doing the explaining goes on the right.

The result is stored in fit so that later steps can re-use it without running the analysis again.

6. Reading the ANOVA results table

Slide: "Step 2 — Compare the groups (ANOVA)" 
            Df Sum Sq Mean Sq F value Pr(>F)
group        4   27.4    6.84   1.821  0.131
Residuals   95  356.8    3.76

Each column has a specific meaning. You only need to read one of them to get the answer — but knowing what the others mean helps you understand why.

ColumnPlain meaning
Df Degrees of freedom. For groups: number of groups minus 1 (5 groups → 4). For Residuals: total rows minus number of groups (100 rows − 5 → 95). You do not need to calculate these; R does it automatically.
Sum Sq / Mean Sq How much variation is explained by the groups (27.4) versus how much is unexplained noise within groups (356.8). Mean Sq is just Sum Sq divided by Df. A large group Sum Sq relative to the Residuals Sum Sq suggests a real effect.
F value The ratio of group signal to leftover noise: 6.84 ÷ 3.76 = 1.821. A larger F means the groups are more separated relative to the noise. There is no fixed threshold — the p-value converts it into a probability.
Pr(>F) This is the p-value. It is the only column you need to read to reach a conclusion. Everything else feeds into computing it.

7. Understanding the p-value

Slide: "One number you'll see everywhere: the p-value"

The p-value answers a specific question:

What the p-value asks If the groups were truly identical in the population, how often would random chance alone produce differences at least this large?

In this data: p = 0.131. That means: if there were genuinely no treatment effect, you would still see differences this large about 13% of the time just by chance. That is too often to be confident the effect is real.

The conventional threshold is 0.05 (5%). Below it, the result is called statistically significant — meaning the differences are unlikely enough to be due to chance that we can claim they are probably real.

p-valueConclusion
p < 0.05 Probably real. The groups differ more than chance would usually produce.
p > 0.05 Not enough evidence. The observed differences could easily be random variation.
Three things the p-value does NOT mean
  • p > 0.05 does not mean the groups are identical. It means the data does not give enough evidence to claim they are different. Absence of evidence is not evidence of absence.
  • p-value is not the size of the effect. A tiny, unimportant difference can be statistically significant with a large enough sample. Always look at the actual means alongside the p-value.
  • 0.05 is a convention, not a law. p = 0.049 and p = 0.051 are essentially the same. The line is a useful rule of thumb, not a sharp boundary between "true" and "false."

R also prints significance stars next to each p-value as a quick visual guide:

0 '***'   0.001 '**'   0.01 '*'   0.05 '.'   0.1 ' '

More stars = smaller p-value = stronger evidence. No star (or a dot) means the result did not reach the 0.05 threshold.

8. Finding which groups differ — Tukey's test

Slide: "Step 3 — Which groups differ? (post-hoc)" 
TukeyHSD(aov(correct ~ group, data = short))

Suppose ANOVA had found a significant result — p below 0.05. That would only tell you that somewhere among the five groups there is a real difference. It does not tell you which groups are different from which others.

Tukey's Honest Significant Difference test answers that follow-up question. It compares every possible pair of groups and gives each pair its own p-value, already adjusted for the fact that you are running many comparisons at once.

                    diff    lwr    upr  p adj
MO_ONLY-CONTROL     0.30  -1.40   2.00  0.988
ECIG_ONLY-CONTROL  -0.10  -1.80   1.60  1.000
MO_ECIG-CONTROL    -1.15  -2.85   0.55  0.337
MO_ECIG-MO_ONLY    -1.45  -3.15   0.25  0.134

Read each row as a comparison between two groups. The columns mean:

  • diff — how much the means differ between the two groups.
  • lwr / upr — the range the true difference probably falls within. If this range crosses zero, you cannot confidently say which group is higher.
  • p adj — the adjusted p-value for that specific pair. Below 0.05 means that particular pair differs significantly.

In this data, no pair reaches 0.05 — consistent with the overall ANOVA result of p = 0.131. The Tukey test is most useful after a significant ANOVA, to locate where the difference sits.

9. Checking whether ANOVA was even valid

Slide: "Step 4 — Is the standard test even valid?" 
shapiro.test(residuals(fit))
bartlett.test(correct ~ group, short)

ANOVA is a reliable test — but only when the data meets two conditions. These two lines check those conditions.

Think of it this way: before using a thermometer to diagnose a patient, you verify that the thermometer is reading correctly. These tests verify that ANOVA is the right instrument for this data.

TestWhat it checks · how to read it
shapiro.test(...) Shapiro–Wilk. Checks whether the residuals (the leftover differences after removing group averages) follow a roughly bell-shaped distribution — one of ANOVA's assumptions. A p-value below 0.05 is a warning: the distribution is too skewed or irregular for ANOVA to be fully reliable.
bartlett.test(...) Bartlett test. Checks whether the spread of scores is similar across all groups — ANOVA's other main assumption. Again, p below 0.05 is a warning: the spreads differ too much.
Important: the direction is reversed here For ANOVA, TukeyHSD, and Kruskal–Wallis, a small p-value (below 0.05) is the result you are looking for. For Shapiro–Wilk and Bartlett, a small p-value is a warning flag — it means the assumption has failed. The p-value itself works the same way; what changes is what you want that p-value to be.

In this data, both checks returned p below 0.001 — a strong signal that the assumptions were violated. This means the ANOVA p-value of 0.131 cannot be fully trusted, and an alternative test is needed.

10. What to do when ANOVA is not valid — Kruskal–Wallis

Slide: "Step 5 — Use the test that fits" 
kruskal.test(correct ~ group, data = short)

The Kruskal–Wallis test asks the same question as ANOVA — do the groups differ? — but makes no assumption about the shape or spread of the data. It works by converting the raw values into ranks (1st, 2nd, 3rd…) and comparing those ranks across groups, rather than comparing the raw means.

You read its output the same way: look at the p-value.

chi-squared = 7.051,  df = 4,  p = 0.133

Here, p = 0.133 — above 0.05. The conclusion is the same as ANOVA: no significant group difference. The fact that both tests agree strengthens that conclusion. But the important point is that we only know they agree because we checked. If assumptions had been fine, the ANOVA result alone would have been sufficient. If they had disagreed, we would have trusted the Kruskal–Wallis result, since it makes fewer assumptions. Always check first.

Why the output says "chi-squared" Kruskal–Wallis uses a chi-squared value internally to compute its p-value. This is a mathematical detail — it does not make it the same as a chi-squared test. A chi-squared test (chisq.test()) is a different thing entirely, used for count data in categories. The cheat sheet explains both. Do not confuse them.

11. The factorial model — asking two questions at once

Slides: "Where R leaves point-and-click behind" and "The factorial view sees what one test misses" 
summary(aov(correct ~ term * group, data = d))

The experiment has two factors: which treatment group the rat belongs to, and which type of memory was being tested (short-term or long-term). Instead of running a separate ANOVA for each, the * operator fits one model that answers three questions simultaneously:

  • Does the memory type matter overall? (term)
  • Does the treatment group matter overall? (group)
  • Does the treatment's effect depend on which memory type was tested? (term:group — the interaction)

The results:

             Df Sum Sq Mean Sq F value Pr(>F)
term          1    0.7    0.72   0.189  0.664
group         4   35.6    8.91   2.342  0.056 .
term:group    4   13.7    3.42   0.900  0.465
Residuals   190  722.3    3.80

Memory type alone (term) makes no significant difference (p = 0.664). The group effect is marginal (p = 0.056 — just above the threshold, marked with a dot). The interaction is not significant (p = 0.465), meaning the treatment's effect on correct entries does not depend on whether the short-term or long-term task was used.

This single model replaces what would otherwise be two separate ANOVAs, uses all 200 observations at once rather than 100, and explicitly tests the interaction — something separate tests cannot do. That is why it "leaves point-and-click behind": most simple software requires several separate tests to answer what R handles in one line.

12. The complete workflow in one view

Every slide, every function, every test fits into this sequence. Print or bookmark this page and use it to orient yourself whenever the slide discussion moves faster than expected.

#QuestionR function
1Do I have the data in R? read.csv("file.csv")
2What did R actually receive? str(d) · head(d)
3What is the average for each group? tapply(d$y, d$group, mean)
4Are the groups statistically different? aov(y ~ group, data=d) then summary(fit)
5If yes — which specific groups differ? TukeyHSD(fit)
6Was ANOVA the right test to use? shapiro.test(residuals(fit)) · bartlett.test(y ~ group, d)
7If not — what test should I use instead? kruskal.test(y ~ group, data=d)
8Can I ask two questions at once? aov(y ~ a * b, data=d)
The most important idea Try not to think of R as "doing statistics." Think of it as answering a sequence of questions. Each function answers exactly one question. Once you know which question each function answers, the analysis stops feeling like a wall of code and starts feeling like a conversation with your data.
