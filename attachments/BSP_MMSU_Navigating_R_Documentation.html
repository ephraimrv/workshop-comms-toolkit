When you use R, you are using a tool built by thousands of researchers and developers over many years. Every function in R — read.csv(), aov(), summary(), tapply() — comes with a built-in reference page that explains exactly what it does, how to use it, and what every option means.

This reference system is called R documentation, and learning to use it is the single most important step between following a handout and using R independently. This guide walks you through how to find that documentation, what it looks like, and how to read every part of it — including the parts that look confusing at first.

1

Asking R for help directly

The fastest way to look up any function is to type a question mark followed by its name in the Console pane — the panel in the lower-left of RStudio. Type it and press Enter.

# Type this in the Console, then press Enter ?read.csv

R immediately opens the full documentation for read.csv() in the Help tab — the panel in the lower-right of your screen. No internet connection is needed. The documentation is installed on your computer together with R itself.

You can also write it as a function call. Both forms produce exactly the same result:

help(read.csv)
Using RStudio without typing If you prefer to click rather than type, look for the search box in the top-right corner of the Help pane. Type a function name there directly and press Enter — no need to go to the Console at all.
2

How to read a help page

Every R help page follows exactly the same structure. Below is a representation of what you will see when you type ?read.csv. Each section of the page is labelled and annotated so you know what it is telling you.

RStudio Help pane — read.csv {utils}
Description 
Reads a file in table format and creates a data frame from it, with
cases corresponding to lines and variables to fields in the file.
A plain summary of what the function does. Read this first to confirm you have the right function for the task.
Usage 
read.csv(file, header = TRUE, sep = ",", quote = "\"",
         dec = ".", fill = TRUE, comment.char = "", ...)
The full function signature — every option you can control. Items written as name = value already have a built-in default; you only need to supply the ones you want to change. Section 3 explains this in full.
Arguments 
file           the name of the file to be read, as a text string in
               quotation marks. Example: "mydata.csv"

header         a TRUE/FALSE value indicating whether the first row of
               the file contains column names. Default: TRUE.

sep            the character used to separate fields. For comma-separated
               files this is a comma. Default: ","

dec            the character used for decimal points in the file.
               Default: "." (a period)
Each option explained one by one, in plain language. When a line of code is not doing what you expect, read the Arguments section carefully — the explanation is almost always here. Not every argument is shown above; scroll down on the real page to see all of them.
Details 
This function is a wrapper around read.table() with different defaults.
It expects a comma-separated file where the first row contains
variable names.
Not every help page has a Details section, and it is not always necessary to read it. It contains longer technical explanations of edge cases and special behavior. Skip it until the Description and Arguments do not give you the answer you need.
Value 
A data frame containing a representation of the data in the file.
What the function gives back to you — the output. For read.csv(), the output is a data frame: the table-like structure you work with in R. This section tells you what you can do with the result.
Examples 
## Read a CSV file from your working directory
df <- read.csv("mydata.csv")
head(df)

## Read a file that uses a semicolon instead of a comma
df2 <- read.csv("mydata.csv", sep = ";")
Real, runnable R code. You can copy any line from the Examples section directly into your Console or script and run it. This section is one of the most useful parts of any help page — especially when you want to see how a function is meant to be used before trying it yourself.
The single most useful habit to build When a line of code behaves unexpectedly, go to the help page for the function and read the Arguments section. Nine times out of ten, the explanation is already there.
3

What default values mean

Look at the Usage line again. Arguments written as name = value — with an equals sign — already have a value that R uses automatically unless you override it. These are called default values. Arguments without an equals sign have no default; you must supply them yourself.

read.csv(file, header = TRUE, sep = ",", quote = "\"", dec = ".", fill = TRUE, comment.char = "", ...)
Required — you must provide this Has a default — R fills it in automatically ... passes additional options through to other functions (advanced — not needed at this stage)

What this means in practice

When you write read.csv("mydata.csv"), you are supplying only the one required argument: the file name. R fills in everything else using the defaults. The short form and the full form below produce exactly the same result:

# Short form — R fills in the rest automatically df <- read.csv("mydata.csv") # Full form — identical result; every default written out explicitly df <- read.csv("mydata.csv", header = TRUE, sep = ",", quote = "\"", dec = ".", fill = TRUE, comment.char = "")

When you need to change one of the defaults, you only need to name that one argument. Everything else stays at its default value:

# The file uses semicolons, not commas — change only sep df <- read.csv("mydata.csv", sep = ";")
Common source of confusion read.csv() always expects a comma-separated file because its default is sep = ",". If your data file uses a different separator — semicolons, tabs, or spaces — you must change this argument. If you forget, R will try to read the entire row as a single column, and your data will appear to have only one variable.
4

When you do not know the function name

Sometimes you know what you want to do — run a correlation, draw a bar chart, test for normality — but you do not know which R function handles it. Two question marks search all installed documentation for a word or phrase:

# Search all installed documentation for anything about "correlation" ??correlation # Alternative, identical result help.search("correlation")

R returns a list of matching functions. Each result shows the package name, the function name, and a brief description. Use ? to open the full page for whichever looks relevant.

One ? versus two ?? ?read.csv — you know the exact function name. Opens its page directly.

??correlation — you know what you want to do, not the function name. Searches all installed documentation.
5

Running the examples on a help page

Every help page ends with an Examples section containing real, runnable code. Rather than copying that code manually, R can execute it for you in one command:

# Run all the examples from the read.csv help page automatically example(read.csv)

R runs every line in the Examples section and shows the output in the Console. This is useful when you want to see a function in action before using it on your own data — you can observe the inputs, the outputs, and the expected behavior without writing any code yourself.

Why this matters for learning independently If you encounter a function you have not used before, example(function_name) is often the fastest way to understand what it does. The examples are written by the same people who built the function.
6

Finding packages and their documentation

R can be extended with packages — collections of additional functions contributed by researchers worldwide. The official repository where packages are stored is called CRAN (Comprehensive R Archive Network):

https://cran.r-project.org/

When you install a package with install.packages("packagename"), R downloads it from CRAN. Every package on CRAN has a page that includes:

  • A plain-language description of what it does
  • A Reference Manual — the complete documentation for every function in the package
  • Vignettes — longer, tutorial-style guides that walk through a real problem from beginning to end

Accessing vignettes directly from inside R

You do not need to visit the CRAN website to read vignettes. If a package is already installed, you can open its vignettes from within RStudio:

# See a list of all vignettes for an installed package browseVignettes("ggplot2") # Open a specific vignette by name vignette("ggplot2-specs")
Start with vignettes when learning a new package Vignettes are written as tutorials, not reference lists. If a package has vignettes, they are almost always the most beginner-friendly starting point — far more readable than a raw function reference.
7

The tidyverse — a family of packages with clear documentation

Several of the most widely used packages for data analysis in R belong to a family called the tidyverse. These packages were designed to work together and are known for their readable, beginner-friendly documentation. The main website is:

https://www.tidyverse.org/

Each package has its own dedicated documentation site with a function reference, a getting-started guide, and worked examples:

Package What it does Documentation
ggplot2 Graphs and charts ggplot2.tidyverse.org
dplyr Filtering, grouping, and summarizing data dplyr.tidyverse.org
readr Reading data files into R readr.tidyverse.org
tidyr Reshaping and cleaning data tidyr.tidyverse.org
8

Official R manuals

For a comprehensive written reference, the R project maintains a set of official manuals at:

https://stat.ethz.ch/R-manual/R-devel/doc/html/

The most useful manual for workshop participants is An Introduction to R. It covers the fundamentals of the language from the ground up and is the authoritative starting point for anyone learning R seriously:

https://stat.ethz.ch/R-manual/R-devel/doc/manual/R-intro.html
