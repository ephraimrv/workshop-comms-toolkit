Leave this structure exactly as it is. Don't rename folders, don't move the data/ subfolders out, and don't merge the two datasets together — the two folders are deliberately separate (molecular vs. non-molecular).

One rule: where your own script goes

When you write your own R script for an exercise, save it inside the dataset folder you're working with — next to its data/ subfolder, not inside it. For example, a script working with the soil dataset should sit directly inside Soil_16S_V4_V5_Molecular_data/, alongside the README and the other .html files.

The one step that makes this work on any computer

This is the part that matters, and it's the same on Windows and Mac — no need to hunt for your file path or type it out.

In RStudio, with your script open, go to
Session → Set Working Directory → To Source File Location

That's it. From then on, in that session, you can load a file using a short relative path — for example:

soil_otu <- read.csv("data/soil.otu.csv")

— and it will work whether your project folder sits on your Desktop, in Documents, or anywhere else, on either operating system.

A quick sanity check after doing this: run getwd(). It should print the path ending in the dataset folder you're currently working in (e.g. .../Soil_16S_V4_V5_Molecular_data). If it doesn't, the working directory didn't update — repeat the step above with the correct script tab active.

Optional, for later: once you're comfortable, look up RStudio Projects (File → New Project) and the here package — they remove the need to set the working directory by hand at all. Not needed for this workshop, but worth knowing it exists.
