The worry from the evaluation forms

"I don't think I can use this on my thesis."

The gap is not R, and it is not statistics. It is the shape of your data — and that is entirely fixable. By the end, R will have done a full analysis on real thesis data.

Why R can't read a thesis spreadsheet directly

A spreadsheet is usually built for a human's eye:

  • Group names sit in banner rows, not in a column
  • The header row repeats for every group and every day
  • Tallies are tick-marks (\), not numbers
  • Merged cells and blanks hide where a table starts and ends

R reads a file as one rectangle: a single header row, then data. A grid built for reading has no single rectangle — so R gives up.

The three rules

  • One row per trial — here, one row per rat per test.
  • One column per variable — term, week, group, replicate in their own columns, never as banners.
  • One header row, at the top, once. One value per cell — no arm-path like 1,7,2,6,4,6,8 crammed into a single cell.

Every rule fixes one problem from the previous slide. This is the skill worth owning — everything after is R doing the work.

Save it as a CSV

A CSV is your table saved as plain text — commas between the cells. Every spreadsheet program makes one (Excel, Sheets, Numbers → Save As / Export → CSV).

term,week,group,replicate,time_min,correct,incorrect,...
short,1,CONTROL,1,1.58,4,3,...
short,1,CONTROL,2,2.03,4,4,...
open the template, do Save As → CSV

Step 1 — Read it, and look at it

d <- read.csv("ecig_memory.csv")            # load the file
str(d)                                      # what did R read?
head(d)                                     # first few rows
short <- subset(d, term == "short")        # short-term trials only
tapply(short$correct, short$group, mean)    # group averages
CONTROL  MO_ONLY  ECIG_ONLY  MO_ECIG  DPL_ECIG
   6.05     6.35       5.95     4.90      5.35
In plain terms

Always look before testing. R already reads the file, reports every column's type, and gives you the group averages — four commands in.

read.csv, str, head, tapply

One number you'll see everywhere: the p-value

What it answers

If there were really no difference between groups, how often would plain luck alone produce a gap this big?

p below 0.05
rarely by luck →
probably real
p above 0.05
could easily be luck →
can't claim it

It tells you whether there's a difference — not how big, not how important. 0.05 is just the usual line.

Step 2 — Compare the groups (ANOVA)

fit <- aov(correct ~ group, data = short)
summary(fit)
            Df Sum Sq Mean Sq F value Pr(>F)
group        4   27.4    6.84   1.821  0.131
Residuals   95  356.8    3.76
Reading it

F = signal ÷ noise (bigger = groups more separated). Pr(>F) is the p-value: 0.131, above 0.05 — this much difference in correct entries could be chance, so we cannot claim a group effect yet. (This test is ANOVA; GraphPad runs the same one.)

run the ANOVA

Step 3 — Which groups differ? (post-hoc)

TukeyHSD(aov(correct ~ group, data = short))
                    diff    lwr    upr  p adj
MO_ONLY-CONTROL     0.30  -1.40   2.00  0.988
ECIG_ONLY-CONTROL  -0.10  -1.80   1.60  1.000
MO_ECIG-CONTROL    -1.15  -2.85   0.55  0.337
MO_ECIG-MO_ONLY    -1.45  -3.15   0.25  0.134
In plain terms

ANOVA says "a difference exists somewhere"; this says which pairs. The p adj column is each pair's p-value, corrected for testing many at once. Here no pair clears 0.05 — consistent with the borderline overall result.

run TukeyHSD

Step 4 — Is the standard test even valid?

shapiro.test(residuals(fit))              # roughly bell-shaped?
bartlett.test(correct ~ group, short)     # similar spread?
Shapiro–Wilk:  W = 0.855,  p < 0.001
Bartlett:      K² = 30.45,  p < 0.001

Both p-values are below 0.05 → the data does not behave the way ANOVA assumes. So the p = 0.131 above is not trustworthy here.

(These two checks are named Shapiro–Wilk and Bartlett — the "is this test appropriate?" step.)

run both checks

Step 5 — Use the test that fits

kruskal.test(correct ~ group, data = short)
chi-squared = 7.051,  df = 4,  p = 0.133
standard ANOVA
p = 0.131
"no difference"
the fitting test
p = 0.133
"same conclusion"
The real lesson

Same data, same conclusion — but we only know that because we checked. Both assumption tests failed badly (p < 0.001). If we had skipped the check and trusted ANOVA blindly, we would have been right by luck, not by method. Always check; you cannot know in advance whether the tests will agree.

Where R leaves point-and-click behind

The data has two memory types: short-term and long-term. Instead of analysing each separately, one factorial model tests groups, memory type, and whether the group effect differs between them — three questions at once.

summary(aov(correct ~ term * group, data = d))
             Df Sum Sq Mean Sq F value Pr(>F)
term          1    0.7    0.72   0.189  0.664
group         4   35.6    8.91   2.342  0.056 .
term:group    4   13.7    3.42   0.900  0.465
Residuals   190  722.3    3.80
In plain terms

Short-term vs. long-term makes no overall difference (term p = 0.664). The group effect is marginal (p = 0.056) — just above the line, but worth noting. The non-significant interaction (p = 0.465) means each treatment's effect on memory does not depend on which memory type was tested. MO_ECIG shows the lowest correct entries in both terms (4.9 short, 5.4 long).

The factorial view sees what one test misses

Run the same memory data as a factorial model instead of short-term alone:

summary(aov(correct ~ term * group, data = d))
             Df Sum Sq Mean Sq F value Pr(>F)
term          1    0.7    0.72   0.189  0.664
group         4   35.6    8.91   2.342  0.056 .
term:group    4   13.7    3.42   0.900  0.465
Residuals   190  722.3    3.80

The one-way on short-term alone gave p = 0.131 — no group effect. The factorial model on all 200 rows pulls group to p = 0.056 — a marginal signal that using only half the data had hidden. Same data, more of it, sharper question.

run the two-way and compare

The whole analysis, start to finish

  1. Inspect — str, head, group means, a boxplot
  2. Compare groups — aov() (ANOVA)
  3. Find which pairs — TukeyHSD()
  4. Check the test is valid — shapiro.test, bartlett.test
  5. Switch test if needed — kruskal.test
  6. Ask richer questions — factorial aov(y ~ A * B)

Every step is one short line. Together they are a complete, defensible analysis — and all of it ran in base R, no packages installed.

The takeaway

The hard part is shaping your data.
That part you can own today.

Lay your data out with the three rules → Save As CSV → read.csv(). From there, R produces real analysis on your own thesis data — and far more of it than a single click ever gives you.

Deciding which result to trust comes with time, or with your statistician. Getting your data R-ready, and seeing what R can do with it, is yours right now.
