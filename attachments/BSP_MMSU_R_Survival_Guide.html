1. Reading the materials: what is code, and what isn't

First: open the materials in a web browser

The workshop materials are .html files. They are meant to be opened in a browser — Chrome, Edge, Firefox or Safari. If you open one by double-clicking and it appears as a wall of angle brackets, you are looking at the file's underlying source code rather than the document:

<div class="section level2">
<h2>Import the dataset</h2>
<p>Run the following:</p>

That is not a broken file and it is certainly not something to paste into R. It means the file opened in a text editor such as Notepad. Close it and instead right-click the file → Open with → your browser. The document will then appear normally, with headings, formatting and proper code blocks.

Then: not every grey box is code

The workshop materials contain grey boxes. Not every grey box is something you run. Some are code. Some are diagrams, illustrations, or examples of what output looks like. Copying a diagram into the console will produce a confusing error.

Before copying anything, ask: is this an instruction to R, or a picture?

This is code — run it

soil_otu <- read.csv("data/soil.otu.csv")
library(ggplot2)
head(kinetics)

Signs it is code: function names followed by round brackets (); the assignment arrow <-; a dollar sign $; filenames in quotation marks; the word library.

This is a diagram — do not run it

Metadata
Feature table
Taxonomy
Phylogenetic tree
        ↓
One analysis-ready phyloseq object

Signs it is not code: arrows such as ↓ or →; plain English nouns listed on separate lines; no brackets anywhere; box-drawing characters; it reads like a description rather than an instruction.

This is output — do not run it either

[1] 120   4

Output is what R gives back to you after running something. It is printed in the materials so you can check your result matches. Lines beginning with [1] are almost always output, not input.

Rule of thumb If a block has no round brackets, no <-, and no quotation marks, it is almost certainly not code. When unsure, ask before running it — it takes five seconds and saves five minutes.

2. Reading the console: >, +, and questions

The console tells you what it is waiting for. Learning to read the first character of the line solves a surprising number of problems.

You seeIt meansWhat to do
> R is ready and waiting for a command. Type or paste your code normally.
+ R thinks your command is unfinished — usually a missing closing ) or ". It is not frozen. Press Esc to cancel, then retype the line with the bracket or quote closed.
A question ending in : or (yes/no) R is asking you something and waiting for an answer, not for code. Type just the letter or word it asks for, then press Enter.
The most common mistake in Session 1 During installation, R may pause and print something like: 
Old packages: 'MASS', 'nlme', 'survival'
Update all/some/none? [a/s/n]:
This is a question, not a prompt for code. Notice there is no > at the start of the line. The [a/s/n] tells you the only three valid answers: a for all, s for some, n for none.

Type a single letter — almost always n — and press Enter. Typing library() or any other R code here will not work, because R is not listening for code at this moment.
Why "none" is usually the right answer Packages such as MASS, nlme and survival ship with R itself and are almost always fine as they are. Updating them mid-installation can introduce new problems for no benefit. Answer n and carry on; update deliberately on a day when you have time to deal with anything that breaks.

3. Installing packages: warnings you can ignore, and ones you cannot

The single most important thing in this section R distinguishes between a warning and an error. A warning is R telling you something it thought you should know; the work usually still succeeded. An error means the operation stopped. Red text in the console is not automatically a failure. Before assuming an install failed, test it directly: 
library(phyloseq)
If the package loads without complaint, it installed correctly — regardless of how alarming the preceding messages looked.

"Installation paths not writeable" — this one is harmless

Several Windows participants saw a message resembling:

Installation paths not writeable, unable to update packages
  path: C:/Program Files/R/R-4.6.1/library
  packages:
    boot, class, cluster, KernSmooth, lattice, MASS, Matrix, mgcv,
    nlme, nnet, rpart, spatial, survival

This looks like a serious failure. It is not. The package you asked for was installed successfully. This message concerns a different set of packages entirely.

Those thirteen packages are R's recommended packages — they arrive with R itself and live in C:/Program Files/, a folder Windows protects. R was installed there with administrator rights, so an ordinary user account cannot modify them afterwards. When something asks R to update them, R reports that it cannot, and then carries on. Your own packages are installed somewhere else entirely, in a personal library that is writable.

Where this message comes from It is usually the consequence of answering something other than n to the Update all/some/none? [a/s/n]: question described in Section 2. Answering n avoids the whole situation, because nothing then attempts to update the protected folder in the first place.
Do not run RStudio as administrator to "fix" this It is a tempting workaround and it causes lasting problems: packages installed as administrator may then be unusable, or not visible, from your normal account. The recommended packages do not need updating for this workshop. Leave them alone.

Two different failures that look alike

MessageMeaning and fix
there is no package called 'dplyr' Not installed. Run install.packages("dplyr"), then library(dplyr).
could not find function "%>%" Installed, but not loaded in this session. Run library(dplyr).

Installing is done once per computer. Loading must be done once per session — every time you restart R.

Bioconductor packages are not on CRAN

phyloseq and similar packages come from Bioconductor, not CRAN, so the usual install.packages() will not find them:

install.packages("BiocManager")
BiocManager::install("phyloseq")

Note the spelling: BiocManager — B-i-o-c. Not "BioManager".

The Rtools warning (Windows only)

Some Windows participants saw a warning that Rtools is missing or out of date. Mac users will never see this — Rtools does not exist for macOS.

Rtools is a set of compilers. It is only required when a package has to be built from source code on your machine. Most of the time R downloads a ready-made version instead, and no compiler is needed. That is why the warning appeared for some people and not others: it depends on whether a ready-made version existed for your exact version of R.

If R asks whether you want to install from source, and offers a choice:

Answer "no" Answering no tells R to use the ready-made version instead. It installs faster, and it does not need Rtools at all. The ready-made version is usually slightly older, which does not matter for this workshop.

Only install Rtools if a package genuinely cannot be obtained any other way — and if that happens, ask rather than guessing, because it is a large download and rarely the real fix.

4. When an installation is interrupted

During Session 1 the internet connection dropped while some participants were installing packages. This deserves its own section because, unlike the other problems in this guide, an interrupted installation can leave damage behind that only appears later, in a form that looks unrelated to the internet.

What you may see at the time

cannot open URL '...'
unable to access index for repository ...
Warning: download had nonzero exit status

Reconnect, and simply run the installation command again. Usually that is the end of it.

What may happen afterwards

If R was part-way through writing a package when the connection failed, it may leave behind a marker folder named 00LOCK or 00LOCK-<packagename>. Until that folder is deleted, R cannot install anything into that library — including packages that have nothing to do with the one that failed. The message looks like this:

ERROR: failed to lock directory '.../win-library/4.6' for modifying
Try removing '.../win-library/4.6/00LOCK-phyloseq'
How to recover
  1. Close all other R and RStudio windows, then restart your current session: Session → Restart R.
  2. Run these two lines: 
    install.packages("pacman")
pacman::p_unlock()
  3. Try your installation again.
If that does not work, the folder can be deleted by hand — but the path is long and easy to get wrong, so please ask rather than guessing. Deleting the wrong folder in a library directory creates a worse problem than the one you started with.

Two habits that avoid this entirely

  • Install before the session, not during it. Thirty people downloading packages simultaneously over one connection is exactly when interruptions happen.
  • Let an installation finish. Do not close RStudio, restart the machine, or run a second install in another window while one is in progress. Most lock folders are created by an install being interrupted rather than by the network alone.

5. Where your files live

Most "file not found" errors are not really about the file. They are about R looking in the wrong folder.

Use an R Project — this is the method that lasts

An R Project ties a folder to your work permanently. Open the project, and R is already looking in the right place — every time, including after restarting your computer.

File → New Project → Existing Directory → [choose your dataset folder]

Create one project per dataset folder, pointing at Soil_16S_V4_V5_Molecular_data or BALO_Bacteriophage_Nonmolecular_data — not at the parent folder. This is what makes the paths printed in the materials work exactly as written.

The temporary alternative

If you have not made a project, you can set the folder manually for the current session only:

Session → Set Working Directory → To Source File Location

This works, but it is forgotten as soon as R restarts, and you must repeat it every time. Use a project instead wherever you can.

Check it in two commands

getwd()
list.files("data")

getwd() should end in your dataset folder. list.files("data") should list the CSV files. If both look right, your paths will work.

Do not rearrange the workshop folders Leave the folder names and the data/ subfolders exactly as delivered. The code in the materials is written against that structure. Renaming or moving folders is a common cause of errors that look like something else entirely.

6. Error message decoder

Message or symptomUsual cause and fix
object 'kinetics' not found The chunk that creates it was never run, or failed. Re-run the import step.
cannot open file / does not exist Wrong folder. Check getwd(), then list.files("data").
could not find function "ggplot" library(ggplot2)
could not find function "%>%" library(dplyr)
object 'time_hr' not found R is case-sensitive. Time_hr, time_hr and TIME_HR are three different names. Check with names(kinetics).
unexpected symbol / unexpected input Usually curly quotation marks from copying out of a document. Retype the " characters by hand.
Console shows + and seems stuck Press Esc. An unclosed bracket or quotation mark.
The plot is empty The filter matched nothing. Check table(kinetics$Metric) and dim() of the filtered data.
figure margins too large The Plot pane is too small. Drag it larger and run the plot again.
Red stop sign in the console corner R is busy, not broken. Wait, or click it to interrupt.
Installation paths not writeable Harmless on Windows. Your package installed. Confirm with library(...). See Section 3.
failed to lock directory / 00LOCK Left over from an interrupted install. Restart R, then pacman::p_unlock(). See Section 4.
cannot open URL Connection dropped. Reconnect and run the command again.
A wall of <div> and <p> tags The materials opened in a text editor. Right-click → Open with → your browser.
Nothing happens when you press Run Your cursor is in the Console rather than the Script pane, or no line is selected. Ctrl/Cmd + Enter runs the current line.

7. Before you raise your hand

Not because asking is unwelcome — it is not — but because these three checks solve most problems faster than waiting, and working out the answer yourself is how the skill actually sticks.

  1. Read the error message. R's messages are terse but honest. The words "not found", "cannot open", and "could not find function" each point at a different problem.
  2. Run getwd(). If R is looking in the wrong folder, several unrelated-looking errors all resolve at once.
  3. Check you ran the earlier chunks. Most "not found" errors are a skipped step further up, not a mistake in the line you are on.

If none of those helps, ask — and when you do, say what you typed and what the message said. That is usually enough to identify the problem immediately.
