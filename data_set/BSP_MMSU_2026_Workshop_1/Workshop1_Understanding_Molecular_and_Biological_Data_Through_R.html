1. Getting started in RStudio

1.1 Create an R Project

In RStudio:

File → New Project → Existing Directory or New Directory

Choose or create a folder called:

Workshop1

An R Project helps R know where your files are. This reduces problems with file paths and working directories.

Pro Tip: Start every new research project with an R Project. It keeps your files organized and makes your work easier to reproduce.

1.2 Check your working directory

The working directory is the folder where R is currently looking for files.

{r check-working-directory, eval=FALSE} getwd()

If you are using an R Project, the working directory should usually be your project folder.

1.3 List the files in your project

{r list-files, eval=FALSE} list.files()

Check the files inside the data/ folder:

{r list-data-files, eval=FALSE} list.files("data")

If R cannot find your data, this is one of the first commands to run.

Pro Tip: Always check getwd() and list.files() before importing files. Many beginner errors are simply file path problems.

3. Importing research data into R

Before importing a file, ask three questions:

  1. What is the file extension?
  2. Which package reads this file?
  3. Do I need to decompress it, or can R read it directly?

3.1 Common file types

File type What it usually contains Common R function
.csv Comma-separated spreadsheet data read_csv()
.xlsx Excel workbook read_excel()
.tsv Tab-separated spreadsheet data read_tsv()
.txt Plain text data read_delim() or read.table()
.fasta DNA or protein sequences readDNAStringSet()
.fastq.gz Compressed raw sequencing reads readFastq()

Pro Tip: A .fastq.gz file does not need to be decompressed before reading it in R. ShortRead::readFastq() can read compressed FASTQ files directly.

4. Getting to know your data

After importing any dataset, inspect it before doing analysis.

4.1 First-look functions

Question Useful functions
What does the data look like? head(), tail(), View()
How big is the dataset? dim(), nrow(), ncol()
What variables do I have? names(), colnames()
What data types are present? str()
What are the basic summaries? summary()

Pro Tip: Never start plotting or running statistics until you have looked at your data first.

5. Importing and inspecting metadata

Metadata describe your samples or observations. They provide the context needed to interpret your data.

For example, metadata may contain:

  • Sample ID
  • Site
  • Treatment
  • Replicate
  • Host organism
  • Collection date
  • Environmental variables

5.1 Import metadata from CSV

{r import-metadata-csv, eval=FALSE} metadata <- read_csv("data/metadata.csv")

5.2 Inspect metadata

{r inspect-metadata, eval=FALSE} head(metadata) tail(metadata) dim(metadata) names(metadata) str(metadata) summary(metadata)

Open the metadata in a spreadsheet-like viewer:

{r view-metadata, eval=FALSE} View(metadata)

5.3 Questions to ask

  • How many samples are in the dataset?
  • How many variables are present?
  • Which variables are categorical?
  • Which variables are numeric?
  • Are there missing values?
  • Are the sample names consistent?

Pro Tip: Metadata are often more valuable than you think. They explain what your samples actually represent.

6. Importing and inspecting a feature table

A feature table is a structured table of biological measurements.

In microbiome data, it may look like this:

  • Rows = taxa, ASVs, OTUs, or biological features
  • Columns = samples
  • Cells = counts or abundances

In other biological research, a similar table might contain genes, species, metabolites, traits, or measurements.

6.1 Import a feature table

{r import-feature-table, eval=FALSE} otu <- read_csv("data/otu_table.csv")

6.2 Inspect the feature table

{r inspect-feature-table, eval=FALSE} head(otu) dim(otu) names(otu) str(otu) summary(otu)

6.3 Questions to ask

  • What do the rows represent?
  • What do the columns represent?
  • Are sample names consistent with the metadata?
  • Are the values counts, proportions, or measurements?
  • Is the table in the orientation expected by the next analysis step?

Pro Tip: Before plotting or running statistics, inspect the dimensions, column names, and a few rows of your table.

7. Importing taxonomy information

Taxonomy files connect feature IDs to biological names.

For example, a taxonomy table may connect an OTU or ASV ID to:

  • Kingdom
  • Phylum
  • Class
  • Order
  • Family
  • Genus
  • Species

7.1 Import taxonomy table

{r import-taxonomy, eval=FALSE} taxonomy <- read_csv("data/silva_taxa.csv")

7.2 Inspect taxonomy table

{r inspect-taxonomy, eval=FALSE} head(taxonomy) dim(taxonomy) names(taxonomy) str(taxonomy)

7.3 Questions to ask

  • Which column contains the feature ID?
  • Which columns contain taxonomy levels?
  • Are the feature IDs consistent with the feature table?
  • Are there unknown or unclassified taxa?

8. Reading FASTA files

A FASTA file is a plain text sequence file. It may contain DNA, RNA, or protein sequences.

A FASTA record usually has:

>sequence_name
ATGCGTACGTAGCTAGCTAG

8.1 Import FASTA

{r read-fasta, eval=FALSE} fasta <- readDNAStringSet("data/reference.fasta")

8.2 Inspect FASTA

{r inspect-fasta, eval=FALSE} fasta length(fasta) names(fasta)[1:5] width(fasta)[1:5]

8.3 Questions to ask

  • How many sequences are present?
  • What are the sequence names?
  • How long are the sequences?
  • What do these sequences represent?

Pro Tip: A .fasta file is usually plain text. You can often open it with a text editor, but R gives you better tools for inspecting many sequences at once.

9. Reading FASTQ files

FASTQ files contain raw sequencing reads. Each read has:

  1. A read identifier
  2. A DNA sequence
  3. A separator line
  4. Quality scores

FASTQ files are often compressed as .fastq.gz.

9.1 Import FASTQ

{r read-fastq, eval=FALSE} reads <- readFastq("data/Mock_R1.fastq.gz")

9.2 Inspect FASTQ

{r inspect-fastq, eval=FALSE} reads length(reads) id(reads)[1:3] sread(reads)[1:3] quality(reads)[1:3]

9.3 Read lengths

{r fastq-read-lengths, eval=FALSE} read_lengths <- width(sread(reads)) head(read_lengths) summary(read_lengths)

9.4 Questions to ask

  • How many reads are in the file?
  • What do the read identifiers look like?
  • How long are the reads?
  • What do the quality scores represent?

Pro Tip: Inspect your raw data before analysis. Raw files often explain problems that appear later in the workflow.

11. Common beginner errors

Errors are part of working in R. They are not a sign of failure.

11.1 File not found

This usually means the path or filename is wrong.

{r file-not-found-example, eval=FALSE} read_csv("data/metadta.csv")

Check:

{r troubleshoot-files, eval=FALSE} getwd() list.files() list.files("data")

11.2 Package not found

This usually means the package is not installed.

{r package-not-found-example, eval=FALSE} library(readxl)

If needed:

{r install-readxl-example, eval=FALSE} install.packages("readxl") library(readxl)

11.3 Object not found

This usually means the object was not created or the previous code chunk did not run.

{r object-not-found-example, eval=FALSE} head(my_data)

Check the Environment pane and make sure the import code ran successfully.

Pro Tip: Errors are clues, not failures. Read the message carefully before trying to fix the code.

12. If I Were Learning R Today

Lessons from the Age of AI

If I were learning R today, I would focus on habits rather than memorization.

  1. Start with your data, not with R.
  2. Learn the workflow, not just the functions.
  3. Use AI to explain code, but not to replace scientific thinking.
  4. Read error messages carefully.
  5. Keep every project organized from the beginning.
  6. Document what you do.

BSP Tip: R helps you work with data. AI can help you learn R. Neither replaces biological understanding.
